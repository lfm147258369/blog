# [NOIP2004 普及组] 火星人

## 题目描述

人类终于登上了火星的土地并且见到了神秘的火星人。人类和火星人都无法理解对方的语言，但是我们的科学家发明了一种用数字交流的方法。这种交流方法是这样的，首先，火星人把一个非常大的数字告诉人类科学家，科学家破解这个数字的含义后，再把一个很小的数字加到这个大数上面，把结果告诉火星人，作为人类的回答。

火星人用一种非常简单的方式来表示数字――掰手指。火星人只有一只手，但这只手上有成千上万的手指，这些手指排成一列，分别编号为 $1,2,3,\cdots$。火星人的任意两根手指都能随意交换位置，他们就是通过这方法计数的。

一个火星人用一个人类的手演示了如何用手指计数。如果把五根手指――拇指、食指、中指、无名指和小指分别编号为 $1,2,3,4$ 和 $5$，当它们按正常顺序排列时，形成了 $5$ 位数 $12345$，当你交换无名指和小指的位置时，会形成 $5$ 位数 $12354$，当你把五个手指的顺序完全颠倒时，会形成 $54321$，在所有能够形成的 $120$ 个 $5$ 位数中，$12345$ 最小，它表示 $1$；$12354$ 第二小，它表示 $2$；$54321$ 最大，它表示 $120$。下表展示了只有 $3$ 根手指时能够形成的 $6$ 个 $3$ 位数和它们代表的数字：


| 三进制数  | 代表的数字 |
| :---: | :---: |
| $123$ |  $1$  |
| $132$ |  $2$  |
| $213$ |  $3$  |
| $231$ |  $4$  |
| $312$ |  $5$  |
| $321$ |  $6$  |

现在你有幸成为了第一个和火星人交流的地球人。一个火星人会让你看他的手指，科学家会告诉你要加上去的很小的数。你的任务是，把火星人用手指表示的数与科学家告诉你的数相加，并根据相加的结果改变火星人手指的排列顺序。输入数据保证这个结果不会超出火星人手指能表示的范围。

共三行。  
第一行一个正整数 $N$，表示火星人手指的数目（$1 \le N \le 10000$）。  
第二行是一个正整数 $M$，表示要加上去的小整数（$1  \le  M  \le  100$）。  
下一行是 $1$ 到 $N$ 这 $N$ 个整数的一个排列，用空格隔开，表示火星人手指的排列顺序。

## 输出格式

$N$ 个整数，表示改变后的火星人手指的排列顺序。每两个相邻的数中间用一个空格分开，不能有多余的空格。

##  思路
- 把问题简化为枚举三个位置上不同数字的组合，符合条件的组合要满足所用火柴数字为n并且满足左右A+B=C的等式。
- 把数字0——9的火柴数存到数组中
```cpp
int num[N] = {6, 2, 5, 5, 4, 5, 6, 3, 7, 6};
```
- 每次枚举令层数x加1，然后火柴数为上一次的火柴数加上当前数字的火柴数。
```cpp
dfs(int x, int sum)
{
    if (sum > n)
        return;
    if (x > 3)
    {
        if (arr[1] + arr[2] == arr[3] && n == sum)
        {
            res++;
        }
        return;
    }
    for (int i = 0; i <= 1000; i++)
    {
        arr[x] = i;
        dfs(x + 1, sum + num[i]);
        arr[x] = 0; // 恢复现场
    }
}

```

- 火柴数就是组成每一个数字所需要的火柴，要计算火柴数就先要把每一位数字拿出来，然后加上它对应的火柴数。
```cpp
int cal(int x)
{
    if (num[x] > 0)
        return num[x];
    else
    {
        int sum_fires = 0;
        while (x)
        {
            sum_fires += num[x % 10];
            x /= 10;
        }
        return sum_fires;
    }
}
```

- 防止超时必须要进行剪枝，因为我们只需要计算符合要求的组合，当sum(当前枚举火柴数)已经大于我们要求的火柴数n了，那么之后枚举的火柴数只会越来越大且跟答案没关系，我们就要剪断这些没有用的分支、
```cpp
if (sum > n)
        return;
```

- 计算火柴数更好的优化
```cpp
// 预处理火柴数
    for (int i = 10; i <= 1000; i++)
    {
        num[i] = num[i % 10] + num[i / 10];
    }
```

类似于计算阶乘时的记忆化搜索，把已经计算的分支存起来，这样就不需要再次展开。
比如在计算数字199的火柴数的时候，按照原来的方法，要把每一位也就是“1”，“9”，”9”分别拿出来，但是我们看上述的方法可以知道，19的火柴数已经算过了，就不需要再次展开19为数字1和9再展开，这样就大大优化了时间复杂度。


# [# P2036 PERKET](https://www.luogu.com.cn/problem/P2036)

## 题目描述

Perket 是一种流行的美食。为了做好 Perket，厨师必须谨慎选择食材，以在保持传统风味的同时尽可能获得最全面的味道。你有 $n$ 种可支配的配料。对于每一种配料，我们知道它们各自的酸度 $s$ 和苦度 $b$。当我们添加配料时，总的酸度为每一种配料的酸度总乘积；总的苦度为每一种配料的苦度的总和。

众所周知，美食应该做到口感适中，所以我们希望选取配料，以使得酸度和苦度的绝对差最小。

## 刚开始思路
- 把酸度求和，苦度求乘积的数值放到数组中。但是不知道怎么存进去，又怎么找出最小差的绝对值。
- 怎么用dfs来搜索？

### 关键点：

1. **组合生成**：需要生成所有可能的非空子集（至少选择一种配料）。例如，对于3种配料，可能的组合有{1}, {2}, {3}, {1, 2}, {1, 3}, {2, 3}, {1, 2, 3}等。
2. **计算酸度和苦度**：对于每个子集，分别计算酸度乘积和苦度之和。
3. **绝对差**：计算每个组合的酸度和苦度的绝对差，并记录最小的绝对差。
4. **剪枝**：在DFS过程中，可能会有一些情况可以提前结束当前路径的搜索，比如当前的绝对差已经比记录的最小差大，那么可以不再继续下去。

### DFS思路：

- 使用一个递归函数来尝试添加或不添加每个配料。
- 对于每个配料，有选择和不选择两种情况。
- 如果选择某个配料，则更新当前的总酸度和总苦度，然后递归处理下一个配料。
- 如果不选择某个配料，则直接递归处理下一个配料。
- 在每次选择完一个子集后，计算并更新最小的绝对差。
- 递归结束条件是处理完所有配料。

### 示例：

假设你有3种配料，酸度分别为`s1, s2, s3`，苦度分别为`b1, b2, b3`。DFS可能会这样进行：

- 选择第一个配料，酸度乘积为`s1`，苦度之和为`b1`，递归处理第二个配料。
- 对于第二个配料，可以继续选择（酸度乘积为`s1*s2`，苦度之和为`b1+b2`）或不选择。
- 对于第三个配料，同样可以继续选择或不选择。
- 在处理完一种组合后，计算酸度和苦度的绝对差，并更新最小值。

### 注意事项：

- 酸度是乘积，苦度是求和。
- 可以用一个变量来记录当前最小的绝对差。
- 由于必须选择至少一种配料，所以初始的最小差可以设为一个较大的数，比如`INT_MAX`。

## 做题思路
1.**将酸度和苦度分别存入两个数组中方便后续的取用**
```cpp
for (int i = 1; i <= n; i++)
    { 
        cin >>acid[i] >> bitter[i];
    }
```
2.**因为每种调料有选和不选两种情况，所以创建dfs函数，先递归解决这两种不同情况**
```cpp
void dfs(int x, int mul, int sum)
{
    
    //选
    st[x] = true;
    dfs(x + 1, acid[x]*mul, bitter[x]+sum);
    // 不选
    st[x] = false;
    dfs(x + 1, mul, sum);
}
```

3.**当x大于n的时候，说明所有的调料情况已经列举完了，形成一个组合了，就要进行检查处理**

- 首先要检查这个组合是不是合法的，因为题目要求我们至少要选择一种调料，所以就要检查这个组合有没有至少选了一种调料，那么每一种调料有没有选择，就可以用一个bool数组st来记录每种调料有没有选
```cpp
void dfs(int x, int mul, int sum)
{
    if (x > n)
    {
        bool has_selected = false;
        //题目要求至少选一种,要检查是不是至少选了一种调料，不能出现一个调料都不选的组合
        for (int i = 1; i <= n; i++)
        {
            if (st[i])
            { 
                has_selected = true;
                break;
            }
        }
        //如果存在合法的组合，那么就要检查它的酸度和苦度绝对值之差，尝试更新答案
        if (has_selected)
        {
            int diff = abs(mul - sum);
            if (diff < min_sub)
                min_sub = diff;
        }

            return;
    }
    //选
    st[x] = true;
    dfs(x + 1, acid[x]*mul, bitter[x]+sum);
    // 不选
    st[x] = false;
    dfs(x + 1, mul, sum)
}
```
- 最后输出答案即可




# [奇怪的电梯](https://www.luogu.com.cn/problem/P1135)

## 题目背景

感谢 @[yummy](https://www.luogu.com.cn/user/101694) 提供的一些数据。

## 题目描述

呵呵，有一天我做了一个梦，梦见了一种很奇怪的电梯。大楼的每一层楼都可以停电梯，而且第 $i$ 层楼（$1 \le i \le N$）上有一个数字 $K_i$（$0 \le K_i \le N$）。电梯只有四个按钮：开，关，上，下。上下的层数等于当前楼层上的那个数字。当然，如果不能满足要求，相应的按钮就会失灵。例如： $3, 3, 1, 2, 5$ 代表了 $K_i$（$K_1=3$，$K_2=3$，……），从 $1$ 楼开始。在 $1$ 楼，按“上”可以到 $4$ 楼，按“下”是不起作用的，因为没有 $-2$ 楼。那么，从 $A$ 楼到 $B$ 楼至少要按几次按钮呢？

## 输入格式

共二行。  

第一行为三个用空格隔开的正整数，表示 $N, A, B$（$1 \le N \le 200$，$1 \le A, B \le N$）。

第二行为 $N$ 个用空格隔开的非负整数，表示 $K_i$。

## 输出格式

一行，即最少按键次数，若无法到达，则输出 `-1`。

## 样例 #1

### 样例输入 #1

```
5 1 5
3 3 1 2 5
```

### 样例输出 #1

```
3
```

## 提示

对于 $100 \%$ 的数据，$1 \le N \le 200$，$1 \le A, B \le N$，$0 \le K_i \le N$。

本题共 $16$ 个测试点，前 $15$ 个每个测试点 $6$ 分，最后一个测试点 $10$ 分。

### 改进建议

1. **使用递归计数**：
    
    - 你需要在 `dfs` 函数中增加一个参数来记录当前已经按键的次数。这个参数可以称为 `steps`。
    - 每次调用 `dfs` 时，增加 `steps` 的值，并在到达目标楼层 `B` 时更新全局的最少按键次数。
2. **记录访问过的楼层**：
    
    - 为了避免重复访问同一楼层，你可以使用一个数组 `visited` 来记录哪些楼层已经被访问过。
    - 每次进入一个新的楼层时，先检查该楼层是否已经被访问过。如果访问过，则直接返回，避免重复计算。
3. **处理边界条件**：
    
    - 在访问新楼层之前，确保新楼层在有效范围内（即 `1` 到 `N` 之间）。如果新楼层不在有效范围内，则直接返回。
    - 如果 `K_i` 为 `0`，则上下按钮都无效，直接返回。
4. **更新最少按键次数**：
    
    - 使用一个全局变量 `minSteps` 来记录从 `A` 到 `B` 的最少按键次数。初始值可以设为一个很大的数（例如 `INT_MAX`）。
    - 当 DFS 到达目标楼层 `B` 时，比较当前的 `steps` 与 `minSteps`，如果 `steps` 更小，则更新 `minSteps`。
5. **终止条件**：
    
    - 如果在DFS过程中，`steps` 已经不小于 `minSteps`，则可以直接返回，因为继续搜索也不会得到更优解。

### 步骤总结

1. **定义全局变量**：
    
    - `minSteps`：用于记录最少按键次数。
    - `visited`：用于记录已经访问过的楼层。
2. **修改 `dfs` 函数**：
    
    - 增加 `steps` 参数来记录当前按键次数。
    - 在进入新楼层之前，检查是否已经访问过。
    - 在到达目标楼层 `B` 时，更新 `minSteps`。
    - 在每次递归调用 `dfs` 时，增加 `steps` 的值。
3. **初始化**：
    
    - 在 `main` 函数中，初始化 `minSteps`。
    - 初始化 `visited` 数组。
4. **调用 `dfs`**：
    
    - 从初始楼层 `A` 开始调用 `dfs`，初始 `steps` 为 `0`。

#include &lt;iostream&gt;
#include &lt;vector&gt;
#include &lt;climits&gt; // 用于 INT_MAX

using namespace std;

int n, a, b;
int minSteps = INT_MAX; // 初始化为最大值
vector&lt;int&gt; arr;        // 用于存储每层楼的 K_i
vector&lt;int&gt; memo;       // 用于记录已经访问过的楼层及其对应的最少按键次数

void dfs(int floor, int steps)
{
    // 如果当前按键次数已经不小于 minSteps，直接返回
    if (steps >= minSteps)
    {
        return;
    }

    // 如果当前楼层已经访问过，并且记录的按键次数不大于当前按键次数，直接返回
    if (memo[floor] != -1 && memo[floor] <= steps)
    {
        return;
    }

    // 记录当前楼层的按键次数
    memo[floor] = steps;

    // 如果到达目标楼层 B，更新最少按键次数
    if (floor == b)
    {
        minSteps = steps;
        return;
    }

    // 计算按“上”按钮后的新楼层
    int upFloor = floor + arr[floor];
    if (upFloor <= n)
    {
        dfs(upFloor, steps + 1);
    }

    // 计算按“下”按钮后的新楼层
    int downFloor = floor - arr[floor];
    if (downFloor >= 1)
    {
        dfs(downFloor, steps + 1);
    }
}

## 疑点
在代码中，`memo`数组用于记录每一层楼的最少按键次数。当算法第一次访问某一层楼时，它会尝试通过按“上”和“下”按钮来移动到新的楼层，并记录到达该层楼所需的最少按键次数。然而，在后续的DFS过程中，可能会再次遇到同一层楼。这时，我们需要判断是否应该继续从这一层楼进行搜索。

具体来说，当算法再次访问同一层楼时，有几种情况：

1. 该层楼的最少按键次数还未被记录（即`memo[floor] == -1`），这时显然需要继续搜索以确定最少按键次数。
2. 该层楼的最少按键次数已经被记录，并且记录的值小于等于当前的按键次数（即`memo[floor] <= steps`），这意味着我们已经找到了一种到达该层楼的方法，而且其按键次数不比当前尝试的路径多。在这种情况下，继续搜索这条路径是没有意义的，因为它不可能产生一个更优的解决方案。

因此，代码中加入`if (memo[floor] != -1 && memo[floor] <= steps)`这一条件判断，主要是为了避免不必要的重复计算。如果当前路径的按键次数不比之前记录的少，那么从这个状态继续DFS下去不可能得到更少的按键次数，直接返回可以减少搜索空间，提高算法效率。

这就是为什么需要记录按键次数不大于当前按键次数的原因，它是为了确保算法在搜索过程中能够快速跳过那些已经被更优路径覆盖过的状态。
